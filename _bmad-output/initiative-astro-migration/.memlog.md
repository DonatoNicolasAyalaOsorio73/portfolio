topic: Portfolio rebuilt on Astro: faster, bilingual URLs, modern motion
updated: 2026-10-28T16:27
---


- (direction) User asked (2026-10-28) to move donacode.link to a modern stack like Astro for much better performance, better animations and cutting-edge motion tech; BMad recommended Astro and the user accepted by asking Sofia to write the initiative.
- (requirement) R1: Every page (home, EcoBike, privacy, 404) ships as prebuilt static HTML; no page compiles templates in the browser or loads React/Babel from a CDN. Reason: in-browser Babel compile on every visit is the main performance cost today.
- (requirement) R2: At launch each page shows the same content, sections, links, images, CV download and EN/ES copy as the current site, checked page by page against production.
- (requirement) R3: Each page has an English URL and a Spanish URL under /es/, each with hreflang alternates and a self-canonical, and the sitemap lists both. Reason: ?lang= cannot vary the head, so Spanish is not indexable today.
- (requirement) R4: Current URLs keep working: /?lang=es, /ecobike.html and /privacy.html (EN and ?lang=es) land on their equivalent page.
- (requirement) R5: Home and EcoBike, EN and ES, meet the performance budget in a Lighthouse mobile run (budget values: see Assumption).
- (requirement) R6: Navigating between pages animates with the View Transitions API where the browser supports it and falls back to a normal page load elsewhere.
- (requirement) R7: The current motion (hero reveal, nav morph on scroll, statement sequence, section reveals) is present and upgraded with scroll-driven effects, and a performance trace while scrolling on a throttled mobile profile shows no dropped-frame runs or long tasks caused by animation.
- (requirement) R8: With prefers-reduced-motion set, non-essential motion is off and every piece of content is visible without scrolling triggers.
- (requirement) R9: Merging to main builds the site and deploys it to donacode.link through GitHub Actions; a pull request runs the build without deploying.
- (requirement) R10: AGENTS.md describes the new stack: how to run, build and preview, where copy and pages live, and the conventions that replace the x-dc runtime rules.
- (constraint) C1 (AGENTS.md Policy): privacy.html stays true: no cookies, no analytics, no third-party requests; fonts, scripts and images are served from donacode.link. A change in stored data updates EN and ES privacy text in the same change.
- (constraint) C2 (AGENTS.md Policy): never push to main; every change lands through a pull request, and merging to main deploys.
- (constraint) C3 (repo CNAME): stays on GitHub Pages at donacode.link; DNS is not changed.
- (constraint) C4 (AGENTS.md Conventions): every visible string has a real Spanish translation; images ship as WebP or AVIF with explicit width and height, no full-size PNGs committed.
- (assumption) Parity first: the visual design stays as it is (branch design/preserve-pass), and the motion layer upgrades it; a visual redesign is out of scope.
- (assumption) Performance budget: Lighthouse mobile Performance >= 95, LCP <= 2.0 s, CLS <= 0.05, and under 50 KB of gzipped JavaScript on the home page.
- (question) Language memory: with /es/ URLs, should the site still store da-lang in localStorage and send returning visitors from / to /es/, or drop storage and let the URL alone decide? Dropping it changes privacy.html (C1). Waits: the user, before the i18n epic.
- (question) Which animation library, if any, beyond native CSS and View Transitions (GSAP, Motion, none)? Waits: bmad-architecture, before the motion epic.
- (event) Self-validate pass 1 (coherence): pass; budget and parity kept as Assumption lines, language memory and animation library as Open questions.
- (event) Self-validate pass 2 (preservation): pass; every claim from the user request and AGENTS.md policy landed in Requirements or Constraints.
- (decision) 2026-10-28 user approved: parity first; the visual design stays and the motion layer upgrades it; a redesign is out of scope (supersedes the parity assumption).
- (decision) 2026-10-28 user approved the performance budget: Lighthouse mobile Performance >= 95, LCP <= 2.0 s, CLS <= 0.05, under 50 KB gzipped JavaScript on the home page (supersedes the budget assumption).
- (decision) 2026-10-28 user chose: drop localStorage da-lang; the URL alone sets the language and / never auto-redirects to /es/; privacy.html EN and ES updated to say nothing is stored (answers the language-memory question).
- (requirement) R11: The site stores nothing in the visitor's browser; the language comes from the URL alone, / never redirects to /es/ by itself, and privacy.html EN and ES say so.
- (event) Spec finalized 2026-10-28: scope approved by the user; slicing into epics next.
- (decision) 2026-10-28 architecture spine adopted as companion of the initiative and both epics; animation library question answered by AD-9 (CSS first, GSAP 3.15 where CSS cannot reach, no Motion).
